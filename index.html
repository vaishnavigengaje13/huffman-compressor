📚 How Huffman Coding Works (Step-by-Step)

1

Frequency Analysis (Hash Map)

Scan the input string/bytes and tally occurrences of each unique character using a Hash Map in $O(N)$ time.

2

Priority Queue Initialization (Min-Heap)

Create a leaf node for each character. Insert all $K$ leaf nodes into a Min-Heap ordered by frequency in $O(K \log K)$ time.

3

Greedy Tree Construction

While the heap has more than one node:

  • Extract the two lowest-frequency nodes ($L$ and $R$).
  • Create a new internal node with frequency = $freq(L) + freq(R)$.
  • Set $L$ as left child and $R$ as right child.
  • Insert the parent node back into the Min-Heap.
4

Prefix Code Assignment

Traverse the resulting binary tree from the root. Traversing left appends 0; traversing right appends 1. Leaf paths define each character's unique prefix-free binary code.

5

Bit Packing & Header Serialization

Map each original character to its binary code. Pack bits 8-at-a-time into true binary bytes. Prepend the frequency table header and padding bit count so the file can be decompressed anywhere.

⚡ Complexity Analysis

Phase Time Complexity Space Complexity
Frequency Count O(N) O(K)
Min-Heap Tree Build O(K log K) O(K)
Code Generation O(K) O(K)
Encoding Bitstream O(N) O(N)
Decoding Bitstream O(N) O(N)

* Where $N$ is total number of characters, and $K$ is number of unique characters ($K \le 256$ for ASCII/byte streams).

🎯 Top 5 Viva / Interview Questions & Answers

Viva Preparation

Q1: What does "prefix-free code" mean, and why is it crucial?

Answer: A code is prefix-free if no character's binary code is a prefix of another character's code (e.g., if 'A' is 01, no other code can start with 01...). This ensures unambiguous decoding without needing any spaces or delimiters between bits.

Q2: Why use a Min-Heap instead of a sorted array?

Answer: When we extract the two smallest elements and push their sum back, an array would take $O(K)$ time per insertion to stay sorted (total $O(K^2)$). A Min-Heap extracts and inserts in $O(\log K)$, reducing overall tree construction to $O(K \log K)$.

Q3: Why is Huffman Coding called a "Greedy Algorithm"?

Answer: At each step of tree construction, it makes a locally optimal choice by immediately merging the two smallest available frequencies. This local greedy choice mathematically leads to a globally optimal prefix tree.

Q4: How does the decompressor handle bit padding?

Answer: Computers store data in 8-bit bytes. If the compressed bitstream is 45 bits, it requires 6 bytes (48 bits), leaving 3 unused padding bits in the final byte. Our file header explicitly records the number of padding bits (e.g., 3) so the decompressor ignores them.

Q5: Can Huffman compression ever make a file larger?

Answer: Yes! For tiny files or high-entropy files (e.g., already compressed JPEGs, encrypted files, or text where every character is unique with frequency 1), the size of the frequency header plus bit alignment can exceed the few bits saved.
